# Daniel实验室 - 标准提示词库

> 目标：整理一份可以直接发给 OpenClaw 使用的标准提示词库。
> 口径来源：
> - `docs/openclaw/asset-sync-sop.md`

## A. 运营线状态更新

### 适用场景
- 更新选题池、内容日历、待改写池、待发布池、审核记录、反馈复盘中的某条状态

### 可直接复制使用的提示词正文
> 按 Daniel实验室 运营线执行模板处理这次状态更新，只允许处理运营线资产，不要扩展到站点代码、站点内容正文、SOP 体系以外的范围。请先判断本次变更属于哪张运营主表，再执行对应飞书更新；如果字段结构、镜像模板或正式规则没有变化，就不要改 GitHub 文档。如果本轮形成了稳定规则或关键状态快照，再按 `asset-sync-sop` 回写 GitHub。完成后汇报：1）更新了哪张表 2）哪条记录状态发生了什么变化 3）是否回写 GitHub 4）当前下一步卡点。若本轮有 GitHub 变更，必须更新 `CHANGELOG.md`。

### 预期产出
- 飞书主控台中的对应状态被更新
- 如有必要，GitHub 中对应镜像 / 规则文档同步更新

### 最低留痕要求
- 飞书必须留下最新状态
- 若 GitHub 有改动，必须更新 `CHANGELOG.md`

### 禁止事项
- 不得改站点源码
- 不得把临时备注升级成正式规则
- 不得跳过飞书主控台只做口头说明

---

## B. 选题推进

### 适用场景
- 新增选题、更新选题优先级、冻结下一篇内容候选、推进某条选题进入母稿阶段

### 可直接复制使用的提示词正文
> 按 Daniel实验室 运营线执行模板处理这次选题推进。任务只限选题池与相关运营资产，不要直接进入正式写稿。请先判断这次动作属于新增选题、更新优先级，还是推进到母稿阶段；先更新飞书主控台中的 `选题池`，再判断是否需要同步 `内容日历` 或 GitHub 侧台账。如果本轮只是日常状态推进，不要新增 SOP；如果形成新的选题规则或排序标准，再回写 GitHub 文档并更新 `CHANGELOG.md`。完成后汇报：1）推进了哪条选题 2）状态如何变化 3）是否进入内容日历 4）是否回写 GitHub。

### 预期产出
- 飞书 `选题池` 状态更新
- 必要时进入 `内容日历`
- 若规则升级，GitHub 文档同步

### 最低留痕要求
- 飞书 `选题池` 必须更新
- 若有 GitHub 变更，更新 `CHANGELOG.md`

### 禁止事项
- 不得直接开始写正式文章
- 不得跳过优先级判断直接排期

---

## C. 母稿生产

### 适用场景
- 新增 Daniel实验室 网站母稿
- 对母稿做正式修订并进入站点内容资产

### 可直接复制使用的提示词正文
> 按 Daniel实验室 内容生产模板执行这次母稿生产，只允许处理本轮指定母稿，不要扩展到无关文章、无关页面或真实发布。请先确认母稿标题、专题归属、站点定位和本轮边界，再在 GitHub 的正式内容目录中新增或修改母稿文件；同时按 `asset-sync-sop` 更新飞书中的待改写状态。如果本轮母稿进入正式站点资产，必须更新 `CHANGELOG.md`。完成后汇报：1）新增或修改了哪篇母稿 2）对应专题是什么 3）飞书哪张表状态已更新 4）下一步是待改写、待审核还是待发布。

### 预期产出
- GitHub `src/content/articles/` 中的正式母稿文件
- 飞书 `待改写池` 中的对应状态更新

### 最低留痕要求
- 母稿必须进入 GitHub 正式内容目录
- 飞书 `待改写池` 必须更新
- `CHANGELOG.md` 必须更新

### 禁止事项
- 不得跳过母稿直接以平台稿作为源头
- 不得把私有草稿 / diary 混入正式内容资产
- 不得直接做真实发布

## D. 平台改写

### 适用场景
- 基于网站母稿生成公众号 / 小红书 / 微博 / 技术博客 / 抖音 草稿
- 根据审核意见修订平台草稿

### 可直接复制使用的提示词正文
> 按 Daniel实验室 内容生产模板执行这次平台改写，只基于现有网站母稿工作，不要另起源头。请根据指定平台生成或修订草稿，并同步更新飞书主控台中的 `待改写池`，必要时更新 `待发布池`。如果本轮只是生成草稿，不要进入真实发布；如果形成新的长期改写规则，再回写 GitHub 模板或 SOP 文档并更新 `CHANGELOG.md`。完成后汇报：1）处理了哪篇母稿的哪个平台版本 2）草稿状态如何变化 3）是否进入待发布状态 4）是否回写 GitHub。

### 预期产出
- 平台草稿文档或草稿内容更新
- 飞书 `待改写池` / `待发布池` 状态更新

### 最低留痕要求
- 飞书改写状态必须更新
- 若 GitHub 模板或正式草稿文档有改动，更新 `CHANGELOG.md`

### 禁止事项
- 不得脱离母稿独立改写
- 不得直接外部发布
- 不得把平台即时反馈误写成长期规则

---

## E. 规则 / SOP 更新

### 适用场景
- 更新资产同步规则、角色模板、发布流程、审核机制、归档边界、主控台规则

### 可直接复制使用的提示词正文
> 按 Daniel实验室 `main+jinhua` 产品化模板执行这次规则 / SOP 更新。先冻结本轮目标、边界和验收标准，再判断本次改动属于 `docs/openclaw/`、`docs/operations/` 还是双留存规则层。请只更新必要的正式文档，不要顺手修改站点功能。规则一旦变化，必须同步更新相关 README 索引与 `CHANGELOG.md`。完成后汇报：1）冻结了什么规则 2）改了哪些文档 3）是否影响飞书主控台口径 4）当前基线是否清楚。

### 预期产出
- GitHub 中的正式 SOP / README / 规则文档更新
- 必要时明确飞书侧应同步的规则变化

### 最低留痕要求
- 规则文档必须更新
- README 索引必须同步
- `CHANGELOG.md` 必须更新

### 禁止事项
- 不得未冻结边界就直接改规则
- 不得只改正文不改索引
- 不得把运营临时状态误写成长期 SOP

## F. 站点资产调整

### 适用场景
- 调整站点结构、页面、布局、正式内容目录、视觉、配置或其他正式公开站点资产

### 可直接复制使用的提示词正文
> 按 Daniel实验室 `main+jinhua` 产品化 / 站点资产模板执行这次站点资产调整。先冻结本轮边界，只处理指定页面、布局、配置或正式内容资产，不要扩展到飞书主控台结构或运营台账。请在 GitHub 主维护面完成改动，并在提交前执行必要的 `check/build`。若本轮影响资产边界、目录结构或长期规则，同步更新 README / SOP / `CHANGELOG.md`。完成后汇报：1）改了哪些站点资产 2）是否影响三类资产边界 3）校验结果如何 4）当前基线是否干净。

### 预期产出
- GitHub 中的正式站点资产更新
- 必要时同步 README / SOP / CHANGELOG

### 最低留痕要求
- 正式代码 / 内容文件必须进入 GitHub
- `CHANGELOG.md` 必须更新
- 若涉及站点资产，必须做 `check/build`

### 禁止事项
- 不得把站点源码迁为飞书主维护资产
- 不得同时顺手修改无关运营线文档
- 不得跳过校验直接提交

---

## G. 阶段复盘 / 里程碑记录

### 适用场景
- 某个阶段完成后，记录本轮建设结论、主控台变化、试运行结果、产品化里程碑

### 可直接复制使用的提示词正文
> 按 Daniel实验室 产品化留痕规则执行这次阶段复盘 / 里程碑记录。请先明确本轮属于运营线里程碑、OpenClaw 产品化里程碑，还是网站资产里程碑，再将关键信息回写到 GitHub 对应日志或规则文档；如果涉及运营执行结果，也同步更新飞书中的审核记录或反馈复盘。不要把一次性的聊天结论直接当成正式里程碑，必须提炼成清晰、可复用的阶段记录。完成后汇报：1）记录了哪个阶段 2）落到哪些文档 / 哪张表 3）新增了哪些可复用结论 4）下一阶段建议是什么。

### 预期产出
- GitHub 中的建设日志 / 阶段记录更新
- 必要时飞书 `审核记录` / `反馈复盘` 更新

### 最低留痕要求
- GitHub 必须留下阶段记录
- 若涉及运营反馈，飞书必须同步更新
- `CHANGELOG.md` 必须更新

### 禁止事项
- 不得把零散聊天内容原样当正式复盘
- 不得只在飞书里留结果不回写 GitHub
- 不得在未完成阶段时硬写“已里程碑化”
