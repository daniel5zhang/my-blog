# Daniel实验室 - 按角色执行模板

> 目标：把 Daniel实验室 后续日常运行中最常用的 3 套角色动作，固化成 OpenClaw 可直接复用的执行模板。
> 本文与 `asset-sync-sop.md` 保持同一口径，不另起规则。

---

## 一、`yunying`：运营线执行模板

### 适用场景
- 更新选题池
- 更新内容日历
- 更新待改写池 / 待发布池
- 回写审核状态、排期状态、反馈复盘
- 做小规模试运行后的状态推进

### 输入要求
执行前至少要明确：
- 当前处理对象属于哪条运营线资产
- 涉及哪篇内容 / 哪个平台 / 哪个状态变化
- 是否只是飞书状态更新，还是需要同步回写 GitHub

### 标准执行口令
- “按运营线模板执行：更新 Daniel实验室 某条内容的排期 / 待发布 / 审核 / 复盘状态。”

### 执行步骤
1. 判断这次变更属于哪张运营主表
2. 先更新飞书主控台对应记录
3. 若字段结构、规则、模板发生变化，再回写 GitHub 文档
4. 若只是临时状态变化，可只留在飞书
5. 每轮结束后更新 `CHANGELOG.md`（若有 GitHub 动作）
6. 汇报本轮变更与当前状态

### 飞书动作
- 更新以下表中的对应记录：
  - `选题池`
  - `内容日历`
  - `待改写池`
  - `待发布池`
  - `审核记录`
  - `反馈复盘`

### GitHub 动作
- 若结构或规则有变化，更新：
  - `docs/operations/bitable-mirror/`
  - `docs/operations/bitable-sync-rules.md`
  - `docs/operations/README.md`

### 最低留痕要求
- 飞书中必须留下最新状态
- 若 GitHub 有改动，必须更新 `CHANGELOG.md`
- 若形成新规则，必须回写正式文档

### 禁止事项
- 不得直接改站点源码
- 不得把临时备注当正式规则写进 GitHub
- 不得跳过飞书主控台，直接只在口头里说“已更新”

### 完成汇报格式
- 本轮更新了哪张运营主表
- 哪条记录状态发生了什么变化
- 是否回写了 GitHub
- 当前下一步卡点是什么

## 二、`creator`：内容生产 / 改写执行模板

### 适用场景
- 新增网站母稿
- 根据母稿生成公众号 / 小红书 / 微博 / 技术博客 / 抖音 草稿
- 更新待改写状态
- 配合审核结论做内容微调

### 输入要求
执行前至少要明确：
- 母稿标题 / 对应专题
- 本轮是写母稿，还是做平台改写
- 是否进入正式站点内容目录
- 是否需要更新待改写池 / 待发布池

### 标准执行口令
- “按内容生产模板执行：新增 Daniel实验室 母稿 / 生成平台草稿 / 根据审核意见修订草稿。”

### 执行步骤
1. 先判断本轮产出属于网站资产，还是运营线改写状态
2. 若写母稿：先在 GitHub 完成正式内容文件
3. 若做平台草稿：按现有模板生成对应平台草稿文档或记录
4. 更新飞书中的待改写池 / 待发布池状态
5. 若内容正式进入站点或仓库，更新 `CHANGELOG.md`
6. 汇报产出文件、状态变化与下一步动作

### 飞书动作
- 更新：
  - `待改写池`
  - 必要时更新 `待发布池`

### GitHub 动作
- 新增或修改：
  - `src/content/articles/`
  - `docs/operations/sample-workflow-*.md`
  - 相关模板文档（如本轮确有变化）
- 更新 `CHANGELOG.md`

### 最低留痕要求
- 正式母稿必须进入 GitHub 正式内容目录
- 改写状态必须进入飞书主控台
- 若草稿规则升级，必须回写 SOP / 模板文档

### 禁止事项
- 不得把本地私有草稿 / diary 混入正式内容资产
- 不得跳过母稿直接把平台稿当源头
- 不得在未确认范围时直接做真实外部发布

### 完成汇报格式
- 本轮新增 / 修改了哪篇母稿或平台草稿
- 已更新哪些飞书状态
- 是否进入正式站点资产
- 下一步是待审核、待发布，还是继续改写

## 三、`main + jinhua`：产品化 / 站点资产执行模板

### 适用场景
- 站点结构调整
- 资产分层与规则冻结
- OpenClaw 产品化 SOP 更新
- 页面、布局、流程机制、站点工程资产变更
- 飞书与 GitHub 双留存机制建设

### 输入要求
执行前至少要明确：
- 本轮属于产品化内容，还是网站资产
- 是否会改站点源码
- 是否会改 GitHub 文档结构
- 是否需要同步影响飞书主控台规则

### 标准执行口令
- “按产品化 / 站点资产模板执行：冻结规则、调整结构、更新站点资产或产品化文档。”

### 执行步骤
1. 先冻结本轮目标、边界、验收口径
2. 判断改动属于：
   - `docs/openclaw/` 产品化资产
   - `src/` 网站资产
   - 或双留存规则层
3. 在主维护面完成改动
4. 若涉及资产边界变化，同步更新 README / SOP / 镜像模板
5. 更新 `CHANGELOG.md`
6. 做 `check/build`（若触及站点或相关仓库内容）
7. 汇报提交结果与当前基线状态

### 飞书动作
- 仅当涉及运营主控台结构、双留存规则或协同入口变化时，更新飞书相关说明或表结构口径
- 不在此模板中直接做运营状态更新

### GitHub 动作
- 更新：
  - `docs/openclaw/`
  - `docs/operations/`
  - `docs/README.md`
  - `src/`（若本轮确实涉及站点资产）
- 更新 `CHANGELOG.md`

### 最低留痕要求
- 每次提交前必须更新 `CHANGELOG.md`
- 规则变动必须更新 SOP
- 资产目录变动必须更新索引 README
- 若触及站点资产，必须做 `npm run check` 和 `npm run build`

### 禁止事项
- 不得在未冻结边界时直接进入实现
- 不得把运营线活状态直接写成站点正式资产
- 不得跳过 README / SOP 更新，只改文件不留口径

### 完成汇报格式
- 本轮冻结了什么目标与边界
- 实际改了哪些产品化文档 / 站点资产
- 是否同步更新了 SOP / README / CHANGELOG
- 当前仓库基线是否干净
