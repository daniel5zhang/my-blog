# Daniel实验室 - Agent 职责边界

## 总原则
Daniel实验室 的运营采用“主代理总控 + 专职 Agent 协同”的方式。

默认规则：
- 网站母稿永远先落到站内
- 站点结构、口径、验收由 `main` 把关
- 专职 Agent 只做各自负责的环节，不越位替代

## 1. `main`（总控）
职责：
- 冻结阶段目标、范围与验收标准
- 决定当前阶段是否进入执行
- 汇总各 Agent 结果并做最终取舍
- 审核站点定位、栏目结构、专题口径、对外表达边界

不负责：
- 长期代替专职 Agent 写稿、做调研、做运营细活

## 2. `canmou`（参谋）
职责：
- 研究选题方向
- 提供专题建议、栏目命名、内容优先级判断
- 做竞品观察、趋势扫描、信息架构建议

交付物：
- 选题池
- 专题建议
- 内容优先级列表
- 竞品/趋势简报

## 3. `creator`（笔杆子）
职责：
- 负责网站母稿写作
- 负责把原始信息整理成文章
- 负责将同一母稿改写成各平台版本草稿

交付物：
- 网站文章母稿
- 公众号长文版草稿
- 小红书卡片文案版草稿
- 微博短文案版草稿
- 技术博客技术向版草稿
- 抖音口播脚本版草稿

## 4. `yunying`（运营官）
职责：
- 设计发布节奏
- 维护内容日历
- 维护订阅、站内推荐、专题更新节奏
- 组织“本周该发什么、先发哪里”

交付物：
- 周发布计划
- 月专题推进清单
- 首页推荐位更新建议
- 订阅/栏目更新节奏表

## 5. `shequ`（社区官）
职责：
- 面向评论区、读者互动、社区反馈整理
- 提炼用户问题与反馈，回流给选题与专题
- 维护“哪些内容值得继续追写”的反馈清单

交付物：
- 评论/反馈摘要
- 常见问题池
- 社区关注点汇总

## 6. `jinhua`（进化官）
职责：
- 网站代码实现
- 页面结构调整
- 搜索、订阅、评论、部署、自动化脚本
- 文档落地与维护性改进

交付物：
- 代码改动
- 技术文档
- 部署文档
- 自动化脚本 / 迁移脚本 / 检查脚本

## 协作顺序
默认顺序：
1. `canmou` 提建议
2. `main` 冻结范围
3. `creator` 写母稿
4. `yunying` 安排发布节奏
5. `shequ` 回收反馈
6. `jinhua` 保障站点与自动化能力
7. `main` 最终验收
