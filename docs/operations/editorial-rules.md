# Daniel实验室 - 站内运营规则

## 1. 站点角色
Daniel实验室 是**文章型内容中枢**。

规则：
- 网站是母稿源头
- 网站先完成内容沉淀与结构化表达
- 外部分发平台后续从网站母稿改写，不反向决定网站结构

## 2. 专题命名原则
专题命名优先满足三条：
- 一看就知道在讨论什么长期问题
- 不跟某一篇文章标题绑定
- 能持续容纳后续新增文章

当前推荐风格：
- `AI观察`
- `自动化实践`
- `数字工作流`

避免：
- 过度追热点的短期栏目名
- 模糊、空泛、无法扩展的命名
- 直接用平台名堆砌专题

## 3. 首页推荐位原则
首页推荐位只放两类内容：
- 值得新读者先看的基石文章
- 能代表当前判断升级的重点文章

不建议：
- 仅因为“最新”就放首页推荐
- 把首页做成资讯流瀑布
- 让推荐位长期不更新

## 4. 文章与专题关系
- 文章是基本发布单位
- 专题是第二主轴，用来把文章重新组织成长期问题域
- 专题页不要求复杂后台，优先保持轻量可维护

## 5. 关于历史 projects 的原则
- `projects` 数据暂时保留
- 前台不再把它作为一级内容类型运营
- 路由仅作历史兼容，不再承担主内容入口职责

## 6. 外部分发关系
后续如果做公众号、小红书、微博、抖音等分发：
- 先在网站完成母稿
- 再按平台风格改写
- 不在本阶段接自动发布
