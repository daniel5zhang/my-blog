## 二、域名/入口切换（DNS Switch）

### 2.1 切换步骤

| 步骤 | 操作 | 预期结果 | 完成时间 |
|------|------|----------|----------|
| 1 | 记录当前 DNS 解析状态 | 记录当前 IP/服务商 | |
| 2 | 更新 DNS A 记录指向新站 | 全球生效前保持旧站可访问 | |
| 3 | 启用 EdgeOne/Cloudflare CDN | 流量切换到新站 | |
| 4 | 验证新站可访问（全球） | 延迟 1-5 分钟生效 | |

### 2.2 注意事项

- **TTL 设置**：提前将 DNS TTL 调低（如 300 秒），便于快速回滚
- **生效验证**：使用多个地点的 DNS 检查工具验证解析生效
- **旧站保留**：切换后旧站保持部署状态 7 天，不下架

## 六、回滚清单（Rollback）

### 6.1 回滚触发条件

出现以下情况时，应立即执行回滚：

- 新站首页无法访问（持续 5 分钟以上）
- 大量文章页面 404（超过 20%）
- 重定向大量失败
- 严重功能缺陷（如搜索、评论无法使用）
- 用户大量投诉

### 6.2 回滚步骤

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | DNS 解析切回旧站 | 域名重新指向旧站 IP |
| 2 | 通知团队回滚开始 | 群通知/邮件 |
| 3 | 确认旧站可访问 | 访问首页和文章 |
| 4 | 关闭新站部署（如需要） | 避免混淆 |
| 5 | 记录回滚原因 | 填写故障报告 |

### 6.3 回滚后行动

- 分析故障原因
- 修复问题
- 重新安排切换时间（建议 48 小时后）
- 更新本 checklist（如需要）
