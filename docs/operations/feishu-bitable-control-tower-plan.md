# Daniel实验室 - 飞书多维表格主控台方案

> 当前原则：飞书多维表格是未来运营主控台；GitHub 是正式内容、规则文档、台账备份和产品建设流程的资产层。
> 当前阶段先完成结构设计与 GitHub 侧镜像，不盲目在外部系统创建真实表。

## 一、主控台目标
Daniel实验室 未来的运营主控台，统一放在一个飞书多维表格 App 中，至少包含 6 张主表：
- 选题池
- 内容日历
- 待改写池
- 待发布池
- 审核记录
- 反馈复盘

主控台职责：
- 承接日常运营动作
- 追踪状态流转
- 为 `main / canmou / creator / yunying` 提供统一协作面板

## 二、6 张主表设计

### 1. 选题池
**用途**：沉淀所有候选选题，做优先级判断与分配。

建议字段：
- 选题标题
- 问题域 / 专题
- 选题类型
- 目标读者
- 核心判断一句话
- 来源 / 线索
- 优先级
- 当前状态
- 负责人
- 计划母稿日期
- 备注

### 2. 内容日历
**用途**：管理周/月内容节奏与发布节奏。

建议字段：
- 日期
- 内容标题
- 内容类型（网站母稿 / 平台草稿 / 运营动作）
- 对应专题
- 对应母稿
- 首发平台
- 状态
- 负责人
- 发布窗口
- 备注

### 3. 待改写池
**用途**：追踪网站母稿完成后，各平台改写草稿的完成度。

建议字段：
- 母稿标题
- 母稿链接 / slug
- 专题归属
- 公众号状态
- 小红书状态
- 微博状态
- 技术博客状态
- 抖音状态
- 当前优先级
- 负责人
- 备注

### 4. 待发布池
**用途**：追踪已具备发布条件、等待审核或排期的内容。

建议字段：
- 内容标题
- 来源母稿
- 平台
- 草稿状态
- 审核状态
- 排期状态
- 还缺什么
- 建议发布时间
- 负责人
- 备注

### 5. 审核记录
**用途**：留痕每次正式人工审核与内部演练结果。

建议字段：
- 审核日期
- 内容标题
- 平台
- 母稿一致性
- 内容质量
- 平台适配
- 品牌口径
- 发布安全
- 审核结论
- 修改建议
- 审核人

### 6. 反馈复盘
**用途**：沉淀发布后的反馈与下一轮优化结论。

建议字段：
- 复盘日期
- 内容标题
- 平台
- 结果概述
- 成功点
- 问题点
- 标题表现
- CTA 表现
- 后续动作
- 回写人

## 三、实施顺序
### 第一阶段（当前）
- 在 GitHub 完成表结构设计
- 建立 6 张镜像模板
- 明确同步规则
- 记录产品建设流程日志

### 第二阶段（下一步）
- 确认安全、明确的飞书多维表格落表目标
- 在飞书创建真实 App 与数据表
- 用 GitHub 模板作为首版结构蓝本

## 四、当前是否具备外部落表条件
当前**还不能安全默认具备外部落表条件**，原因：
- 还没有明确的飞书默认目标位置（文件夹 / 所属空间 / 命名约定）
- 还没有用户明确指定的外部落表容器
- 因此本轮只完成 GitHub 侧方案与备份模板，不执行飞书外部创建
