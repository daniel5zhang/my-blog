# Daniel实验室 - 第一次真实小规模试运行方案

## 1. 首发内容
- 首发内容：`为什么 Daniel实验室 先做网站，不急着做平台自动发布`
- 选择原因：
  - 已完成内部审核演练
  - 能代表 Daniel实验室 当前方法论
  - 对新读者解释力强
  - 与网站战略、首页推荐位、专题挂载保持一致

## 2. 首发平台顺序
### 第一顺位
- 公众号
- 原因：
  - 最适合承接完整方法论表达
  - 能保留母稿的大部分叙事结构
  - 最适合作为第一次真实试运行的主战场

### 第二顺位
- 微博
- 原因：
  - 适合做观点切片
  - 可作为公众号长文的外部引流补充
  - 成本低，便于观察短内容表达是否成立

## 3. 发布时间建议
- 建议先做同一周内的“小联动”，不要同一时刻齐发
- 建议顺序：
  1. 公众号先发
  2. 微博在公众号发布后 2-24 小时内跟进
- 建议发布时间窗口：
  - 公众号：工作日晚间
  - 微博：公众号发布后当天晚些时候，或次日上午

## 4. 成功判断方式
### 视为成功的信号
- 公众号版本读起来顺，不像生硬改写
- 微博版本能独立成立，不像残缺摘要
- 两个平台版本都能自然引导回网站母稿
- 发布后复盘时，能明确看出“母稿 -> 平台改写”的流程没有断层
- 至少能收集到一轮真实反馈，足够支持下一次试运行优化

### 视为失败或需调整的信号
- 平台版本明显像硬切稿，读感差
- 标题方向失焦，导致内容主旨被带偏
- 微博版本过长、过散，无法独立成立
- 公众号版本过于像站内原文复制，缺少平台适配
- 发布后无法回写经验，导致试运行没有形成复利

## 5. 发布后必须回写的反馈
- 哪个平台版本读感最好，哪个最别扭
- 标题是否成立
- CTA 是否自然
- 哪个版本最能承接 Daniel实验室 的品牌判断
- 是否需要调整“首发内容先公众号、再微博”的顺序
- 是否需要在下一轮把小红书纳入第二批试运行

## 6. 本轮边界
- 本方案只用于第一次真实小规模试运行准备
- 不代表现在就执行真实发布
- 不改生产环境变量
- 不进入全平台齐发
