# 旧站迁移与新站切换规划文档

## 一、迁移概述

### 1.1 技术栈变更

| 项目 | 旧站 (my-blog) | 新站 (my-site-v2) |
|------|----------------|------------------|
| 框架 | Hugo | Astro |
| 静态站点生成器 | v0.123.x | v5.x |
| 前端模板 | Hugo 模板 + CSS | Astro 组件 + Tailwind |
| 部署方式 | GitHub Pages / Vercel | Docker + EdgeOne |

### 1.2 内容目录映射

| 旧站路径 | 新站路径 | 迁移策略 |
|----------|----------|----------|
| `content/articles/*` | `src/content/articles/*` | 直接迁移 |
| `content/science/*` | `src/content/articles/*` | 合并迁移，通过 `category: science` 区分 |
| `content/diary/*` | **第一批不迁移** | 暂存旧站，后续处理（见下文） |
| `content/easyclaw/*` | 待定 | 第一批不处理 |
| `content/skills/*` | 待定 | 第一批不处理 |

## 二、迁移分批策略

**完成标志**：

- 分类页面正常渲染

## 三、content/diary 迁移决策

### 3.1 不在第一批迁移的原因

1. **内容性质差异**：日记内容为个人生活记录，与技术/AI 文章风格差异大
2. **分类需要重新设计**：可能需要独立分类或标签页展示
3. **隐私考量**：部分日记可能不适合公开或需要脱敏处理
4. **迁移优先级**：优先迁移核心内容（技术文章），日记可后续处理

### 3.2 后续处理选项（供决策）

| 选项 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| A. 完整迁移 | 将 diary 全部迁移至新站 | 保留全部内容 | 需要重新设计展示方式 |
| B. 选择性迁移 | 仅迁移部分日记（如近期的） | 工作量可控 | 需要人工筛选 |
| C. 保留旧站 | 旧站仅用于日记，保持独立 | 最小改动 | 两套系统维护成本 |
| D. 不迁移归档 | 仅保留旧站入口，不做新站迁移 | 完全不做迁移 | 内容分散 |

**推荐**：第一批完成后，由内容负责人（creator）评估后决定。

## 四、风险评估与应对

### 4.1 风险清单

| 风险 | 严重程度 | 可能性 | 应对措施 |
|------|----------|--------|----------|
| URL 变更导致 SEO 下降 | 高 | 中 | 完整 301 重定向配置 |
| 文章内容丢失 | 高 | 低 | 迁移前完整备份 |
| 分类/标签映射错误 | 中 | 中 | 迁移后人工抽查 |
| Feed 订阅者丢失 | 中 | 中 | 切换期多渠道通知 |
| 回滚期间服务中断 | 中 | 低 | 旧站保持可访问状态 |

### 4.2 回滚思路

1. **DNS 回滚**：域名解析切回旧站 IP/服务
2. **旧站保留**：切换期间旧站保持部署状态，不删除
3. **数据库/内容备份**：迁移前对旧站完整备份
4. **快速回滚流程**：若新站切换后 24 小时内发现严重问题，可一键切回旧站

### 4.3 验收口径

| 验收项 | 验收标准 |
|--------|----------|
| 站点可访问 | 新站首页可正常加载，响应时间 < 3s |
| 文章完整性 | 已迁移文章数量与旧站一致（articles + science） |
| 分类正常 | categories 和 tags 页面可访问，文章数量正确 |
| 重定向正确 | 旧站主要路径（/, /articles, /science）正确跳转 |
| Feed 可用 | /rss.xml 与 /feed.json 可访问，内容列表完整 |
| 移动端适配 | 手机浏览器可正常浏览 |
